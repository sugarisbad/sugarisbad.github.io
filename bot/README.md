# Бот приёма заявок

Telegram-бот — «приёмная» opsmith: принимает заявки с лендинга, показывает
каталог услуг с ценами и FAQ, ведёт учёт заявок и даёт клиенту живой чат с
инженером прямо в боте.

## Что умеет

**Для клиента:**

- **Главное меню** (`/start` без deep-link): заявка, услуги и цены, FAQ,
  «мои заявки», вопрос инженеру, кнопки на сайт и Calendly.
- **Каталог услуг** (`/services`) — 8 направлений, цены совпадают с прайсом
  сайта (`src/data/pricing.ts`); из карточки услуги оформляется заявка в один тап.
- **FAQ** (`/faq`) — те же вопросы-ответы, что и на сайте.
- **Короткая форма заявки** — имя подставляется из Telegram, затем задача →
  способ связи → предпросмотр. Можно выбрать «Связаться здесь» и не вводить
  телефон/почту. Все поля можно исправить перед отправкой.
- **Сохранённые диалоги** — черновики, вложения и шаг формы сохраняются в
  SQLite. После перезапуска `/start` предлагает продолжить, `/resume`
  возвращает к текущему шагу; `/cancel` удаляет текущий черновик.
- **Вложения** — до 10 фото, документов, голосовых, видео, аудио или стикеров
  к заявке. Их также можно отправлять в прямом чате с инженером. Голосовые
  пересылаются как аудио, без распознавания речи.
- **Мои заявки** (`/status`) — номера и статусы своих заявок; при смене статуса
  приходит уведомление.
- **ИИ-консультант** (`/ask`, и на любое «просто сообщение» боту) — при
  настроенной Ollama сам ведёт диалог: выясняет требования, подбирает услуги
  по прайсу, считает предварительную оценку тем же калькулятором, что и сайт
  (с комбо-скидками), и по команде клиента передаёт заявку инженеру — со
  сводкой, оценкой и полным диалогом. Технических решений клиенту не даёт и
  внутреннюю кухню не раскрывает. Кнопка «📨 Передать инженеру» и брошенные
  диалоги дают прямой канал с владельцем; без Ollama чат — просто переписка
  с инженером.

**Для владельца (в ADMIN_CHAT_ID):**

Кнопка «Управление заявками» и команды админки показываются только владельцу
в его личном чате с ботом. Все административные действия проверяют Telegram ID
отправителя и чат; ручной ввод команд или нажатие старой кнопки другим
пользователем не открывает доступ.

- Под каждой заявкой кнопки **✍️ Ответить / 🔧 В работу / ✅ Закрыта** — ответ
  уходит клиенту от имени бота, смена статуса пишется в базу и уведомляет клиента.
- `/stats` — сводка: всего заявок, за 7 дней, по статусам.
- `/admin` (или `/leads`) — списки с пагинацией, фильтры по статусу, поиск,
  карточки заявок, приватные заметки и вложения.
- `/find Иван`, `/find #12`, `/find username` — поиск по номеру заявки,
  Telegram ID, имени, контакту или описанию задачи.
- В карточке заявки — **«Переписка файлом»**: сохранённая переписка с этим
  клиентом в UTF-8 `.txt`, включая обращения по другим его заявкам.
  История начинает записываться после установки обновления.
- **«Ответить»** включает режим отправки текста и вложений выбранному
  клиенту. **«Закончить ответ»** или `/cancel` закрывает этот режим.
- Через 2 часа без ответа приходит напоминание; затем оно повторяется раз в
  сутки. Кнопки позволяют отложить его на час или сутки. Напоминание снимается
  после успешной доставки ответа либо закрытия заявки.

Заявки хранятся в SQLite (`leads.db` рядом с ботом, путь настраивается
через `LEADS_DB`).

### Доставка и обслуживание

Заявка и очередь её уведомлений записываются одной транзакцией. Клиент получает
подтверждение **сохранения**, а доставка инженеру повторяется при сетевых сбоях
с увеличивающимся интервалом (до часа). Части длинных сообщений отправляются
по очереди, HTML и эмодзи сохраняются; лимит каждой части — 3500 UTF-16 единиц.

Блокировка бота получателем или некорректное вложение отображаются в
`/admin → Доставка`. После устранения причины нажмите «Повторить неудачные».
Если соединение оборвалось после принятия сообщения Telegram, но до получения
подтверждения, повтор может продублировать сообщение; дубли самих заявок
предотвращаются уникальным ключом формы.

Очередь, черновики, заметки и история хранятся в той же базе. При обновлении
существующая база расширяется автоматически. Старые заявки со статусом «новая»
также включаются в напоминания.

- `logs/bot.log`: ротация по 5 МБ, пять архивов (всего до ~30 МБ).
- `backups/leads-YYYY-MM-DD.db`: резервная копия при старте и затем ежедневно
  во время работы бота, с проверкой целостности; последние 14 дат.
- Бэкап делается через SQLite Backup API и включает незавершённую очередь.
  Это локальная копия на том же диске.
- Успешно обработанные задания очереди удаляются через 30 дней; заявки,
  заметки и история переписки остаются в базе.

Настройки необязательны, значения по умолчанию:

```dotenv
LOG_DIR=logs
BACKUP_DIR=backups
BACKUP_KEEP=14
REMINDER_MINUTES=120
REMINDER_REPEAT_MINUTES=1440
```

Опционально: если на сервере есть [Ollama](https://ollama.com), бот прогоняет
текст заявки через локальную LLM и прикладывает разбор — суть задачи, подходящая
услуга, срочность и уточняющие вопросы.

## Запуск

1. **Создайте бота**: напишите [@BotFather](https://t.me/BotFather) → `/newbot` →
   придумайте имя и юзернейм (например `sugarisbad_orders_bot`) → получите токен.
2. **Узнайте свой chat id**: спросите у [@userinfobot](https://t.me/userinfobot).
3. **Запустите**:

   ```bash
   cd bot
   python -m venv venv && . venv/bin/activate     # Windows: venv\Scripts\activate
   pip install -r requirements.txt
   cp .env.example .env                            # впишите BOT_TOKEN и ADMIN_CHAT_ID
   export $(grep -v '^#' .env | xargs)             # или задайте переменные вручную
   python bot.py
   ```

4. **Проверьте**: напишите боту `/start`, пройдите форму — заявка должна
   прийти вам в личку.

## Деплой на сервер (systemd) — одной командой

```bash
git clone https://github.com/sugarisbad/sugarisbad.github.io.git site
cd site/bot
sudo ./install.sh        # спросит BOT_TOKEN и ADMIN_CHAT_ID, если нет .env
```

Скрипт создаёт служебного пользователя `tgbot`, ставит бота в `/opt/tgbot`
с виртуальным окружением, устанавливает systemd-юнит и запускает сервис.
Повторный запуск скрипта обновляет `bot.py` и перезапускает сервис,
не трогая `.env`.

Управление:

```bash
systemctl status tgbot        # состояние
journalctl -u tgbot -f        # живые логи
sudo systemctl restart tgbot  # перезапуск
```

<details>
<summary>Ручная установка (если не хочется скриптом)</summary>

```bash
sudo useradd -r -s /usr/sbin/nologin tgbot
sudo mkdir -p /opt/tgbot
sudo cp bot.py admin.py storage.py delivery.py maintenance.py requirements.txt .env /opt/tgbot/
cd /opt/tgbot && sudo python3 -m venv venv && sudo venv/bin/pip install -r requirements.txt
sudo chown -R tgbot:tgbot /opt/tgbot
sudo cp tgbot.service /etc/systemd/system/
sudo systemctl daemon-reload && sudo systemctl enable --now tgbot
```
</details>

## Windows: фоновый запуск

```powershell
cd C:\Users\lolki\sugarisbad.github.io\bot
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\start.ps1
```

`start.ps1` читает `.env` и запускает `pythonw.exe` без консоли. Именованный
mutex защищает от второй копии, запущенной через этот скрипт. Самостоятельно
запускать `bot.py` при работающей задаче не нужно.

На этом компьютере автозапуск настроен задачей **OpsmithTelegramBot** при
входе пользователя в Windows. Управление:

```powershell
Get-ScheduledTask -TaskName OpsmithTelegramBot
Get-ScheduledTaskInfo -TaskName OpsmithTelegramBot
Stop-ScheduledTask -TaskName OpsmithTelegramBot
Start-ScheduledTask -TaskName OpsmithTelegramBot
Get-Content .\logs\bot.log -Tail 30
```

Для смены токена или настроек измените локальный `.env` и перезапустите задачу.
Компьютер должен быть включён, подключён к сети и не находиться в спящем режиме.

Восстановление: остановите задачу и убедитесь, что её процессы Python завершены.
Сохраните текущие `leads.db`, `leads.db-wal`, `leads.db-shm` отдельно, затем
поместите выбранный бэкап вместо `leads.db` (рядом не должно оставаться старых
`-wal`/`-shm`) и запустите задачу. Очередь также вернётся к состоянию бэкапа.

## Проверки

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

Проверки используют временную базу и имитацию Telegram API. Проверяются
миграция, транзакции, перезапуск, повторная доставка, напоминания, длинные тексты,
вложения, права администратора и клиентские сценарии.

## Отслеживание источника заявки (deep-links)

Каждая кнопка «Заказать» на сайте ведёт в бота со своим кодом:
`t.me/<бот>?start=vps-setup`, `?start=plan-ai`, `?start=src-cases` и т.д.
Бот расшифровывает код (словарь `SOURCES` в `bot.py`) и добавляет в заявку
строку «🔗 Откуда: …» — видно, какая услуга или страница привела клиента.
Если добавляете услугу на сайт — добавьте её слаг и в `SOURCES`.

## Подключение к сайту

После создания бота впишите ссылку на него в `src/data/site.ts`:

```ts
botUrl: 'https://t.me/<юзернейм_бота>',
```

На странице появится кнопка «🤖 Оставить заявку в боте» в блоке контактов.

## Лиды в EspoCRM (опционально)

Если у вас развёрнута [EspoCRM](https://www.espocrm.com), бот может создавать
лида из каждой заявки. Добавьте в `.env`:

```
ESPOCRM_URL=https://crm.example.com
ESPOCRM_API_KEY=<ключ>
```

Ключ создаётся в CRM: Администрирование → API Users → создать пользователя
с ролью, у которой есть право `create` на сущность Lead (метод аутентификации
API Key). В лида попадают имя, телефон, почта, Telegram клиента, источник
заявки и текст задачи. Если CRM недоступна, заявка всё равно приходит в
Telegram — доставка от CRM не зависит.

## LLM-разбор (опционально)

На сервере с Ollama добавьте в `.env`:

```
OLLAMA_URL=http://127.0.0.1:11434
OLLAMA_MODEL=gemma2
```

С Ollama бот дополнительно отвечает на вопросы клиентов в чате «вопрос
инженеру» — присылает черновик ответа ИИ, пока владелец не ответил лично.

Если Ollama недоступна, бот просто пришлёт заявку без блока «Разбор» и не
будет присылать черновики — доставка заявок и чат никогда не зависят от LLM.
